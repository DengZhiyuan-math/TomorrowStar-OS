functional charter can be validated, used to create an immutable offline formal
run bundle, replayed from its recorded raw response, and checked against a

workflow, or scoring implementation exists.

Output: packaged Python core, CLI, charter, immutable run/replay contracts,
provenance gate, and deterministic offline tests.

JSON/raw response → strict domain contracts and verifier.

| T-01-01 | Tampering | `FormalRunStore` path boundary | high | mitigate | Resolve the workspace and every destination, reject paths outside it, disallow formal-run destinations that already exist, and write through temporary sibling files followed by atomic replacement | `tests/test_run_store.py` exercises traversal, symlinks, pre-existing destinations, and immutable verification |
| T-01-02 | Tampering | Formal run verifier and replay loader | high | mitigate | Use canonical serialization, a SHA-256 content manifest, strict schema validation, and verification of every declared file before replay | `tests/test_run_store.py` and `tests/test_replay.py` mutate stored bytes and require fail-closed behavior |
| T-01-03 | Tampering | Charter/provenance JSON parser | medium | mitigate | Configure Pydantic with `extra="forbid"`, explicit schema versions, enums for classifications, and no permissive transform fallback | `tests/test_charter.py` and `tests/test_provenance.py` reject unknown fields, absent required fields, and invalid classifications |
