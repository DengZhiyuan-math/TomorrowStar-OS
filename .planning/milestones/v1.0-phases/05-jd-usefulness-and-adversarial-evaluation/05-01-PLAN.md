## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| accepted packet -> comparison core | Caller-supplied structured requirements and policy cross into capability judgment logic. |
| assessment workspace -> reviewed graph envelope | Persisted assessment sidecars and policy ancestry are reopened as claimed user truth. |
| comparison result -> CLI/report | Private JD-derived decisions cross into local console/report projection. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Spoofing | `load_reviewed_user_graph` | high | mitigate | Reopen strict sidecars, resolve current version hashes and active policy ancestry, require exact `reviewed-user-truth`, and reject detached admitted assessments before comparison. |
| T-05-02 | Tampering | accepted packet and `JDMatchPolicy` | high | mitigate | Bind exact source/policy hashes, reconstruct byte spans, use frozen extra-forbidding records, and test malformed/empty/duplicate packets before any score. |
| T-05-03 | Elevation of Privilege | score and route derivation | high | mitigate | Keep mastery aggregation outside the JD module, hash full graph inputs before/after, enforce core caps, and permit only the named evidence route overlay. |
| T-05-04 | Information Disclosure | CLI errors and report header | medium | mitigate | Emit stable IDs/codes and hashes through the existing structured error boundary; exclude raw private JD text and interview answers from routine errors. |
| T-05-05 | Repudiation | policy/route explanation | low | accept | Every result retains canonical policy, input, graph, and result hashes plus an explicit route reason; local single-user execution needs no identity service. |
</threat_model>
