## Phase Goal

**As a** user or evaluator, **I want to** record representative career evidence in a strict Contribution-grounded model, **so that** invalid or unsupported assessment states are rejected.

<objective>
Prove the Phase 2 architecture with one production-quality JSON-to-domain-to-CLI tracer, then expand the strict contracts across all supported Experience types, proof-limited Evidence, claim-level attribution, and independently bounded assessment dimensions.

Purpose: Establish the real executable seam every fixture and negative case in later plans will use, while implementing MOD-01, MOD-03, MOD-04, MOD-05 and D-05 through D-12/D-16 without inferring capability from documentary proximity.
Output: Importable domain contracts, deterministic validation result types, an offline `fixture validate` command, and focused model/CLI tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| JSON file → strict domain core | Untrusted fixture bytes cross into frozen Pydantic contracts and aggregate invariant checks. |
| document-derived Evidence metadata → personal claim fields | Documentary support must not cross into personal responsibility/capability without a reviewed claim state. |
| repeated Evidence/link rows → assessment basis | Duplicate references must not become independent support or alter a score. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-01 | Spoofing | `ContributionClaim` / `ContributionSkillAssessment` | high | mitigate | Require per-claim responsibility, assistance, confirmation status, and claim-level assessment basis; unreviewed/non-user support cannot establish a definite assessment. |
| T-02-02 | Tampering | `Evidence` / `ClaimEvidenceLink` | high | mitigate | Enforce global Evidence IDs, unique Evidence-to-claim links, pinned locators, and content identities before an assessment validates. |
| T-02-03 | Elevation of Privilege | `AssessmentLineage` | high | mitigate | Require Contribution lineage in the tracer and route prohibited source kinds to deterministic invariant rejection expanded in Plan 02. |
| T-02-04 | Information Disclosure | model/CLI tracer | low | accept | This plan uses synthetic checked-in test records only and reads no STOA source, secret, production, user-data, cache, or untracked path. |
</threat_model>
