<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| CLI/process → audit store | Concurrent or stale processes can attempt to overwrite a newer answer, attribution, or review. |
| Disk event history → trusted snapshot | Local files can be deleted, reordered, truncated, or rewritten before resume. |
| Process interruption → durable publication | A crash can occur between metadata replacements and expose split custody. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03G-06 | Tampering | `events.jsonl` full history | high | mitigate | Strict event schema, contiguous sequence, previous-hash links, canonical record hashes, full-chain read verification. |
| T-03G-07 | Tampering / Denial of service | snapshot/event publication | high | mitigate | Exclusive lock, fsynced staged files/journal/directory, deterministic journal recovery, crash-point tests. |
| T-03G-08 | Repudiation | normal and review mutations | high | mitigate | Mandatory expected verified head at store boundary and versioned CLI read/CAS update. |
| T-03G-09 | Information disclosure | event records | medium | mitigate | Retain the existing redacted event projection; hashes and event metadata contain no raw career answers or review text. |
| T-03G-10 | Spoofing | unsafe audit path/lock/journal names | medium | mitigate | Existing audit-ID allowlist, resolved-root containment, generated internal filenames, symlink rejection. |
</threat_model>
