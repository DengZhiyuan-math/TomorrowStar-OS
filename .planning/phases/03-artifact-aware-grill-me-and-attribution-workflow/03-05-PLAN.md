## AuditEventRecord Contract

| Field | Contract |
|---|---|
| `schema_version` | Literal `audit-event/2`; extras forbidden and model frozen |
| `sequence` | Integer ≥ 0; genesis is 0; each later value is predecessor + 1 |
| `action_type` | One of `start`, `answer`, `skip`, `pause`, `resume`, `review-entry`, `review-conclusion` |
| `action_id` | Required stable allowlisted ID for genesis and every later action |
| `action_digest` | Required `sha256:<hex>` of canonical redacted semantic action payload; excludes action ID, expected event head, and expected effective conclusion hash |
| `snapshot_hash` | Required hash of the exact canonical resulting snapshot bytes |
| `prev_event_hash` | Null only for sequence-0 `start`; otherwise required and equal to predecessor `event_hash` |
| `event_hash` | Required hash of canonical event fields above with `event_hash` omitted |

Genesis rejects any non-start type, nonzero sequence, or non-null predecessor. Non-genesis rejects start, null predecessor, repeated/out-of-order sequence, unknown action type/field, missing action identity, and any payload/snapshot/previous/event hash mismatch.

`AcceptedActionResult` is a protected strict record containing schema version, action ID, action digest, committed event hash, result snapshot hash, and the exact canonical result snapshot/state. It contains no CLI projection field and has no projection sidecar. It lives inside the bounded audit directory, is hash-checked against its event, and raw contents never enter the redacted event log. Both first acceptance and exact replay call the same deterministic CLI serializer over this verified snapshot, so replay presentation has no second mutable authority.

## Per-Audit Lock and Mutation Protocol

1. Every custody operation opens the stable root-contained `audits/.locks/<audit_id>.lock` (0600), takes the same exclusive advisory lock, and never deletes/replaces that inode.
2. `read`, `read_versioned`, and `latest_event_hash` call recovery and full snapshot/event/action-result validation under that lock. `read_versioned` returns snapshot plus head from this one critical section.
3. Mutation transaction acquires the lock, recovers/validates, computes strict canonical action digest, then looks up immutable `AcceptedActionResult` by action ID.
4. Existing ID + equal digest returns the recorded original snapshot/result immediately. It ignores old head/status, changes no bytes/mtime, appends no event, and creates no journal.
5. Existing ID + different digest raises controlled collision. New ID then checks required expected event head; stale head rejects before transition.
6. A new action applies the pure lifecycle/effective-hash transition, stages complete snapshot/event/accepted-result files, fsyncs files + journal + directory metadata, publishes in the declared order, fsyncs the directory, and removes the journal.
7. Recovery under the same lock deterministically completes or rejects an interrupted declared transaction before any reader or writer trusts state.

## Trust Boundaries

| Boundary | Description |
|---|---|
| CLI/process → audit store | Concurrent or stale processes can attempt to overwrite a newer answer, attribution, or review. |
| Disk event history → trusted snapshot | Local files can be deleted, reordered, truncated, or rewritten before resume. |
| Process interruption → durable publication | A crash can occur between metadata replacements and expose split custody. |
