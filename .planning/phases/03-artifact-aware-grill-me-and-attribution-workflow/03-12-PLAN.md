<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Caller-selected workspace path to held workspace/root inode | A local filesystem actor can replace the named audits child after a check. |
| Root inode to lock and audit-directory inode | Locks and custody data must be created below the same verified root identity; hard-link aliases cross an otherwise path-invisible inode boundary. |
| Audit inode to journal/snapshot/events/results | Individual file names can be replaced with symbolic or hard links, or the parent path can be rebound during I/O. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-03G4-04 | Tampering / Elevation of privilege | audit-root binding | high | mitigate | O_DIRECTORY/O_NOFOLLOW root fd, lstat/fstat identity binding, held descriptor lifetime, deterministic swap regression. |
| T-03G4-05 | Tampering / Denial of service | `.locks` and lock file | high | mitigate | Exclusive mode-0600 creation, no-follow open, owner/type/mode/single-link admission before flock, no chmod of existing inodes, held fd, and external hard-link regression. |
| T-03G4-06 | Tampering / Information disclosure | audit files and publication journal | high | mitigate | Audit-relative owner/type/mode/single-link admission, mode-0600 exclusive temp creation, destination admission, dir_fd replace/unlink, fsync, and rebind/hard-link regressions. |
| T-03G4-07 | Repudiation | CAS/replay/recovery lineage | high | mitigate | Preserve strict complete-chain validation, identity-first replay, caller-held heads, and deterministic journal recovery under one descriptor-anchored lock. |
