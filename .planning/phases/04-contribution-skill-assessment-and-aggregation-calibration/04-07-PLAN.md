<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repeated CLI command to stored authority | A normal retry must not be interpreted as permission to replace reviewed state. |
| reviewer/reassessment payload to current projection | Human-supplied changes become authority only through expected-hash validation and append-only versions. |
| immutable versions to later consumers | Later phases must be able to resolve every predecessor and distinguish original, corrected, and current states. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-G07-01 | Elevation of privilege | normal assessment rerun | high | mitigate | Return the validated existing record unchanged; forbid collision replacement and require explicit reassessment for new intent. |
| T-04-G07-02 | Tampering | reviewer correction lineage | high | mitigate | Append a new canonical version with expected-current and predecessor hashes; retain every prior complete version. |
| T-04-G07-03 | Repudiation | review/reassessment history | medium | mitigate | Persist reviewer, reason, outcome, source audit, complete effective content, and contiguous hashes in every version. |
| T-04-G07-04 | Information disclosure | CLI error paths | medium | mitigate | Keep structured IDs/codes and continue the existing raw-answer redaction regression on rerun and reassess failures. |
</threat_model>
