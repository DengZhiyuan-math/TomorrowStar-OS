# 02: 单页故障后继续处理其他岗位

**What to build:** 一个岗位页面关闭、崩溃或命令失败后，工作台说明该岗位的故障，worker 保留其他页面并继续处理其他岗位。

**Blocked by:** [01：区分当前运行与历史检查点](01-current-runtime.md)。需要其运行与页面观察绑定。

**Status:** closed

**Parent:** [确定故障隔离、恢复保证与诊断验收标准](../../application-worker-next-stage/issues/02-recovery-contract.md)。

**Specification:** [稳定性阶段：故障隔离、恢复保证与验收规格](../../application-worker-next-stage/assets/stability-contract.md)。

- [x] 首页面在等待前、等待中和命令处理时关闭，均不能结束其他页面或 worker。
- [x] 原生页面崩溃单独识别；受影响岗位进入待核验，未完成动作不丢失。
- [x] 关闭、释放、显示页面或移除守卫的局部命令异常不扩大成批次退出。
- [x] 页面清理只影响目标岗位；未知接管不恢复该页自动写入权限。
- [x] 两页原生浏览器用例证明另一页仍可读、可完成下一合法步骤；故障状态和工作台提示一致。
- [x] T05、T06、T07 的故障隔离断言通过；不能以 mock 事件代替原生崩溃证据。

## 共同边界

- [x] 每票均保持自动最终 Submit 动作和最终请求放行数为零。
- [x] 测试使用隔离合成页面与临时记录；真实岗位不用于反复故障保存或上传。
- [x] 复用现有 worker、答案库、原记录、单实例机制、原生控件与草稿契约；不新增独立浏览器进程或平台队列。
- [x] 个人资料、答案、简历、认证和真实 trace 保持私有；公开验收报告只含合成证据。
- [x] 完成每票时即有自己的演示与测试，不把测试全部推迟到最后一票。
