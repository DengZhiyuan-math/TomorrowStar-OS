# 04: 保留未知保存与上传结果

**What to build:** 保存、上传或挂接结果不明时，用户能看见待核验动作及已知证据。即使响应丢失或检查点写失败，worker 也不会自动重传。

**Blocked by:** [03：控制失联与共同故障后安全暂停](03-safe-batch-pause.md)。检查点写入失败需要其批次停止规则。

**Status:** closed

**Parent:** [确定故障隔离、恢复保证与诊断验收标准](../../application-worker-next-stage/issues/02-recovery-contract.md)。

**Specification:** [稳定性阶段：故障隔离、恢复保证与验收规格](../../application-worker-next-stage/assets/stability-contract.md)。

- [x] 操作意图获得持久授权后才执行；意图写失败时，新发送计数为零。
- [x] 保存动作、文件上传和附件挂接分别留证；传输事件、HTTP 状态和业务核验分开。
- [x] 服务端已应用但响应丢失、报错或业务回读失败时，结果保持未知，自动重传计数为零。
- [x] 回读后最终检查点写失败时，停止新自动动作并保留旧有效文件；存储恢复不自动解除停止。
- [x] 工作台明确显示结果未知及需核验内容，不将历史字段值或缺少请求记录解释为未发送。
- [x] T11、T12 覆盖不同动作与写入阶段；浏览器、服务端计数和状态记录相互核验。
