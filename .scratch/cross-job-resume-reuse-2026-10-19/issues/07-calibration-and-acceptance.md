## Question

怎样证明系统复用得当且确实减少重复生成，而不是只提高复用率？需要哪些对照样本、人工判断与错误边界，才能冻结最初规则或阈值？

## Decision criteria

- 遵循[原型票最新决定](06-selection-experience.md)：复用完全内部化，校准不得新增用户相似度／候选审核或复用专用操作；只检查正常材料结果、必要变动审核及端到端准备效率。
- 建立合成案例矩阵：职责差异、关键要求遗漏、级别差异、语言、同PDF多岗、来源不全、未审核材料、事实冲突、资料新增、用户改选、无历史与恢复。
- 把候选召回、适用判断、材料选择三层误差分开；错误复用不能由节省调用数抵消，不预设漂亮的成功率。
- 核对端到端准备时间及用户重复确认次数，依本票实际答复以重复确认为审核主指标；包含新增检索／重评成本，不能只比较少掉的生成调用数。
- 决定误复用／漏复用／不必要修改的优先级、可接受边界及不能判断时的处理；有标注样本后才校准分数阈值。
- 明确真实历史样本的私有读取范围及既有接受记录来源，不要求用户新增标注；本票只规划，不擅自读取或运行；不依雇主拒信归因质量。
- 指定后续验证需记录生成／编译是否跳过、PDF字节保持、事实来源、当前绑定和人工接受；离线、安装与真实用户接受分别验收。

## Claim — 2026-10-19

用户明确要求开始本票，一次只问一个问题，聚焦内部复用是否加快简历生成、减少审核且不增加用户操作。核对open、未领取及全部直接前置closed/completed后，由01a15509/root领取。只确定校准样本与验收标准，不实际运行模型、生成、编译或私人样本读取，不向用户新增复用审核流程；实际答复逐项记录。

## Discussion — 2026-10-19

### 用户决定：同输入对照，按可审核PDF端到端耗时验收

用户明确确认：“可以，以开始准备到得到可查看、可审核 PDF 的总耗时验收；用同一 JD、同一版已审核资料对比正常生成与内部复用，把检索、检查、修改和编译都算进去，内部计时，不增加我的操作。”因此速度主指标为准备开始到实际可查看、可审核PDF就绪的总耗时，不能只计模型返回、少掉的调用或某一缓存阶段。内部复用带来的检索、材料核验、改稿与编译均纳入，不转移到计时边界之外；正常生成对照保持相同JD及已审核资料版本。若无法得到可用PDF，记录为未成功完成，不当作更快的成功样本。时间自动记录，不要求用户额外开始／停止计时或评判检索过程。具体对照执行及冷热缓存记录方式留给本票后续验收方案整理，不宣称本轮已运行比较。

### 用户决定：审核负担以重复确认次数衡量，未变内容不重审

用户明确回复：“可以，以需要我重新审核的重复确认次数来衡量，系统内部记录，不要求我额外计时或评分；已核验的未变内容不要重复进入审核。”因此审核负担的验收主指标为用户需要执行的重复确认次数，不把代理此前提出的新增／修改文字量视为用户选定的主要指标。系统内部记录，不新增计时、标注、评分或复用审核动作。已核验未变内容不重复进入审核；实际变更的新表述及新PDF仍按已有材料规则确认，不能通过省略必要确认伪装降低重复确认数。具体哪些记录构成同一内容的重复确认，以精确材料／内容版本、审核状态和核验继承关系为依据，不凭点击数总量或文件名粗略推断。

### 用户决定：缩短总耗时且重复确认不增加；既有重复必须消除

用户明确确认：“可以，总耗时确实缩短、重复确认次数不增加就算通过；原本有重复确认的场景，要验证这些重复确认已被消除。”因此不要求每份简历的重复确认数都严格下降，原本为零时可持平；有可核验未变内容被重复确认的基线场景，复用路径须验证该重复确认被消除。不能把省略必要的新版本材料确认视为合格的减少审核。

## Resolution — 2026-10-19

依据本票三次实际答复及前六票已确认边界结案，保留执行者01a15509/root。结案的是校准与验收规格，不是实测结果或功能接受；本轮未读取私人样本、未运行生成／模型／编译或新的用户流程。

### 验收主标准

- 对照相同JD版本、相同当前已审核职业资料版本及相同历史材料可用状态。正常生成基线与内部复用路径使用相同可比的生成／编译环境，不通过更换模型、降低输出要求或故意清除基线已有缓存制造提速。
- 从任务开始准备计到实际可查看、可审核PDF就绪；检索、核验、改稿、编译及必要等待均计入。无法产出有效PDF或发生错误则记录失败／未完成，不按短耗时当作成功。
- 在相同输入的代表性内部对照中，总耗时须确实缩短，重复确认次数不得增加。有既有未变内容重复确认的场景须消除这些重复确认，原本为零可保持零。
- 不增加用户计时、评分、相似度判断、候选比较、标签标注或复用确认。现有正常材料接受及手选替换确认仍适用，不能少做必要确认来优化指标。
- 任何已知违反前票规则的误复用须修复后再验收，不能用速度或平均复用率抵消。内部不可靠时按已确认有限回退生成，不为追求命中率放宽资格、事实或精确材料身份。

### 内部案例矩阵

案例先用合成JD、已审核内容／接受记录及合成材料构造，期望结果由前票规则确定，不要求用户额外逐份标注。

| 案例 | 内部期望及检查 |
| --- | --- |
| 高度相近JD，已有充分适用的有效已接受PDF | 精确原PDF采用，不生成／编译相同材料，不要求重复内容接受 |
| 同名AI工程师但模型工作与客户部署不同 | 不凭名称或共通关键词强行复用；不适用则正常回退 |
| 异名／跨行业但实际任务相近 | 能发现相关历史JD，仍核对关联材料，不先按分类排除 |
| 职级或框架不同 | 可召回参考，不补造责任或替换真实技术名称；直接采用仍须适用 |
| 调序、突出已审核事实或单项目替换 | 局部修改，未变审核经核验继承，不整份重写 |
| 主要选材与整体重点需重组 | 生成新版本，不能为减少审核误用不合适原PDF |
| 简历语言不符合明确要求 | 只能作参考，新语言版本经正常材料接受，不直接采用旧PDF |
| 新增已审核经历或已有事实被更正／撤回 | 只消费上游变更状态并重评材料；无收益可保留，含旧错误PDF不可直接采用，不启动经历准备或匹配采访 |
| 草稿、接受未知、原JD不全、原PDF损坏／丢失 | 遵循候选票的参考／排除／重建规则，不伪装已接受或自动补造JD |
| 同PDF多岗、同岗多版本 | 材料去重但保留真实关联；按适用性选择有效版本，不固定最新 |
| 有限查找无合适候选 | 一次少量扩展后正常生成，不无限搜索，不把未命中说成全库不存在；单列回退成本 |
| 用户手选及输入变更 | 输入未变保留手选，变化后备稿但先提醒并获确认才替换，不新增复用专用界面 |
| 重开、重复请求或评估中输入变化 | 不重复生成／编译同一有效材料，不错用旧输入结果，保留历史 |

### 计量、校准与证据

速度记录配对任务起止、阶段耗时、生成／编译是否发生、PDF可用结果、输入及配置版本。重复确认须区分未变事实／内容的再次确认与实际变更的新表述、新PDF或手选替换的必要接受；记录内部所需确认与正常运行中实际发生的确认，不把计划计数当作已观察的用户行为。

候选召回、关联材料资格、材料采用错误分别记录；召回遗漏可导致安全回退，不等同误复用。排序、相似阈值、少量候选数与查找期限依据以上案例的正确性和总开销校准，而非套用文章参数或预设百分比。实现时选择足以区分波动的重复配对运行，记录顺序、冷热状态及首次JD整理成本；首次整理与后续复用结果分别报告，不只挑最快一例。

直接复用、局部修改、重生成及未命中回退分别报告，不能用均值隐藏查找拖延、失败或个别分支明显退化。未命中等不能节省生成的场景要核对已确认的快速有限回退目标；其查找开销须进入总体比较，不能把这些样本移除来宣称加速。若尚无足以区分噪声的配对结果，则速度结论为未证实，不能仅凭调用数减少通过。

真实历史资料只在后续明确私有范围及执行授权下使用，复用已有接受记录与正常材料结果，不另要求用户建立复用标签库。没有真实日志时只报告合成预期或内部可观察计数，不宣称减少了真实用户次数。不得依雇主拒信或面试结果推断复用质量。

离线正确性、实际生成／编译性能、安装路径及用户正常使用结果分别留证；合成通过不替代真实速度或用户体验接受。后续若需要真实模型或编译，仍按原有具体执行授权处理，本票不启动这些工作。

参数具体值、内部联系日志与最小实现落点由[接入票](08-integration-handoff.md)根据以上标准确定并可校准配置；不要求用户审核工程中间过程。若实测暴露必须由用户裁决的新取舍才新建决策票，本次不凭空扩大范围。
