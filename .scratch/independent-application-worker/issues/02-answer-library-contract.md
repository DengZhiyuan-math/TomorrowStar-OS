## Question

用户补充一次答案后，什么条件下 worker 可直接复用？何时必须重新确认？

“补充后记入信息库”已经确认。本票只决定具体契约：普通资料、国家工作资格、
公司或岗位特定问题各自的适用范围；等价问题别名如何确认；冲突、过期、修改和
撤回如何失效；敏感答案怎样保存与使用；等待中的任务怎样读取新确认版本。
不要把不同国家、时间或条件下的答案自动当成等价。

## Resolution requirements

用合成问题展示最小决策表。每次只向用户提出一个未决问题。
记录用户选择和例外，不重复询问已确认事实。不允许模型推测值成为 confirmed。
worker 必须核对返回记录的实际 scope、确认状态和答案版本，不能把 helper 查找成功当成复用许可。
最终必须覆盖：补充时写入、再次匹配时复用、修正后旧值停止使用，以及无适用答案时等待。

## Answer

### 首次补充与保存

系统提出默认适用范围，用户只修改例外；保存最终范围与用户明确确认的答案。
姓名、联系方式、个人主页默认全局；国家相关资格声明限定国家和具体条件；
公司或岗位特定问答限定公司或岗位。无法判断范围时先限定当前岗位。
范围建议与答案值分别处理，不能根据范围建议生成个人事实。

已确认普通和敏感申请答案默认保存，并在原适用范围内复用。
用户可指定“仅本次，不保存”：仅用于当前申请，不加入可复用答案库。
该例外不代表清除目标 ATS 已收到的内容；若临时答案丢失，不能从未保存的信息中恢复答案。

上游 Job Apply Skill 的敏感值逐次复核规则与本独立 worker 契约不同。
独立 worker 按本次用户明确选择实现复用；存储仍使用 helper 的敏感值同意标记与现有接口。
这项规划不证明当前安装插件已经提供该行为。

### 查找与自动复用

优先已有字段映射、规范化匹配及已知别名。新的措辞也可由系统判断是否与已有问题等价。
等价、实际 scope 匹配且答案仍有效时直接复用，不因措辞或敏感类别重复询问。
等价性必须包含所询问的事实、国家、时态、条件及选项含义；文本相似本身不够。
保存系统识别的等价关系及其来源，保留个人答案的用户确认来源。用户纠正后撤销错误匹配。
具体匹配方式及可信判断标准留给[确定 ATS 适配、上传与人工提交的执行边界](06-ats-execution-boundary.md)。

### 不确定、修改与恢复

无适用确认答案、等价性不确定或答案冲突时，该问题等待用户补充或澄清。
澄清结果及可复用范围记入信息库，避免对同一问题反复询问；“仅本次”除外。
更新、撤回、明确有效期届满或适用条件改变使旧任务准备失效。
恢复前重新读取答案并验证内容版本、实际 scope、确认状态及任务输入版本。
新答案取代原值后，不沿用已填入页面的旧值；重新填表或重新复核对应字段。
没有依据不增加固定周期的重复确认。最终 Submit 仍由用户操作。

### 存储与所有权

复用已核验 helper，不重复实现问题 key 或创建第二份个人资料库。
helper 的查询结果不能充当复用许可，调用方必须核对实际记录。
任务绑定答案内容版本；运行记录只保存必要引用，不复制个人答案值。
门户、worker 和其他答案写入者须使用统一串行入口或共同锁协议。
具体部署、锁和任务状态机制由运行时、输入和恢复票确定，不在本票新增数据库。

### 验收案例

| 合成场景 | 必须得到的结果 |
| --- | --- |
| 首次出现未知问题，用户补充 | 保存已确认答案和实际范围，随后恢复该问题 |
| 新措辞被系统判为等价，范围相同 | 自动复用，不再次询问 |
| 等价性不确定或多个答案冲突 | 请求澄清，结果记入信息库 |
| 国家、时态或条件不同 | 不误用原答案；没有适用答案时等待补充 |
| 薪资等敏感答案已确认且范围未变 | 直接复用，不进行逐次复核 |
| 用户标记“仅本次，不保存” | 当前申请可用，不成为后续可复用答案 |
| 用户修正或撤回答案 | 旧任务准备失效，旧值不再用于填表 |
| 显式期限届满或适用条件改变 | 复用停止，确认新事实后再恢复 |

这些是开发验收要求；本轮完成规划，没有宣称 worker 已通过这些场景。
