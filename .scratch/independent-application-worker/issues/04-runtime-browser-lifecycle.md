## Question

首版用什么最小启动方式独立于 Codex 运行，并如何保留或重建供用户复核的申请页面？

研究已证明 Playwright 可独立运行；不再调查是否必须使用 Codex 浏览器。
本票决定独立 CLI / macOS App 启动、运行时安装和版本固定、可见或 headless 浏览器、
专用资料目录、批次页面上限，以及关闭 Codex、关闭门户、用户退出和电脑休眠时的行为。

## Evidence and assets

- [Playwright 与本地运行事实](../../../research/independent-application-runner-feasibility-2026-10-09.md)。
- [框架固定版本](../../../research/application-automation-framework-sources-2026-10-09.md)。

## Resolution requirements

按最少依赖选择首版交付方式。明确浏览器会话交接和资源上限。
关闭 headless 页面后不能宣称已填表单仍存在；认证 storage_state 不等于表单草稿。
不在本票安装浏览器或创建定时任务。

## Answer

### Web 应用与执行进程

TomorrowStar 本地 Web 界面是控制入口：勾选已有岗位、逐岗位选简历、补充答案、
开始、暂停、继续及显示执行进度。现有原生窗口是可用的界面宿主。
复用现有本地后端接入一个独立 worker 进程；普通用户从原界面操作，无需另建控制应用。
worker 不依赖 Codex 对话或 Codex 内置浏览器。页面关闭、服务退出和 worker 暂停分别处理。

首版采用项目现有 Python 3.13 和 Playwright Python Chromium，单个顺序 worker。
浏览器基础库基线采用已研究的 Playwright Python 1.63.0（Apache-2.0），具体固定来源见
[框架版本、许可证与数据路径](../../../research/application-automation-framework-sources-2026-10-09.md)。
实现时通过锁定依赖和对应浏览器安装固定库与浏览器 build，并记录许可证和版本；
不能因系统 Chrome 更新而隐式换用不同执行浏览器。此处未安装依赖或认定现有 App 已打包它。

答案读写复用已核验的固定 Job Apply helper。部署时验证 helper 版本与来源，
不可用时报告配置问题，不自动切到第二份资料库；独立运行不要求 Codex 浏览器存活。
实际目录显式配置且保存在私人运行区域，不能因初始化而意外导入 legacy 个人资料。

### 专用可见浏览器与页面保留

使用专用可见 Chromium 实例和独立资料目录，由用户在该浏览器完成必要登录。
不复制日常浏览器或 Codex 的认证资料，不并发启动同一 browser profile。
待复核页面由用户直接查看及最终提交。执行器停止自动填写后仍可保留该页面。

暂停时不主动关闭仍有效的申请页面；持有页面的进程可以处于空闲状态。
浏览器自身退出、页面失效、电脑重启或进程崩溃后，已填 DOM 和附件选择不保证保留。
登录资料和任务进度不等于表单草稿；恢复前重查实际页面，需要时重建与重新核验。
不能以重建为由重试最终提交，已有投递或结果不明时进入相应停止状态。

同时保留的页面必须有有限上限。首版建议默认三页，并作为可调整运行配置在原型与验收中核对。
达到上限时等待用户处理，不为继续批处理而关闭未复核页面。资源上限不是已测性能指标。

### 控制页面关闭与暂停

用户已选择关闭 TomorrowStar 后暂停批次。按 Web 架构，关闭控制页面或失去控制连接后，
后端确认控制失联便停止启动新自动步骤，保留可续任务和仍有效浏览器页面。
原生宿主退出可发送明确暂停请求；普通网页关闭须由后端控制连接机制确认，
不能将标签页关闭直接等同服务进程退出或保证瞬时收到通知。
检测窗口、后台标签页、多窗口、正在进行的动作和强制退出由
[确定任务暂停、恢复、取消与去重语义](05-recovery-cancellation.md)定义和验证。

重新打开 TomorrowStar 呈现暂停进度，由用户点击继续；不自动重新执行整个批次。
关闭 Codex 不触发暂停。关闭招聘浏览器会使相关页面无法续接，不当作成功或取消整批。
电脑休眠期间不声称持续处理，恢复后先检查输入、浏览器与状态。
暂停控制不能依赖门户后端必须一直退出或一直运行；要明确保留浏览器的所有权。

### 运行与写入边界

首版没有云队列、常驻定时任务或自动登录启动要求。
worker 领取状态、浏览器所有权和受控写入入口须互相一致，防止重复实例使用同一批次与 profile。
复用已有本地 HTTP 的 Host、Origin、CSRF 与显式私人目录边界，不将控制能力暴露给招聘页面。
系统写入遵守已解决的批次与答案库契约；跨进程协调、崩溃恢复与待同步重试由恢复票确定。

### 验收要求

- 从 TomorrowStar Web 界面启动批次，关闭 Codex 后仍可处理。
- 关闭控制界面触发暂停，重新打开只显示进度，点击继续后才恢复。
- 暂停保留仍有效的可见招聘页面，不把保存状态当成已恢复表单。
- 页面丢失后能识别并重建或等待处理，不重复最终提交。
- 达到页面上限时不销毁待复核页面；并发启动不争用 profile。
- 当前原生 App 的既有退出验收与新 worker 行为分别测试，不以旧测试证明新实现。

这些是规划契约，尚未实现或验收独立运行。
