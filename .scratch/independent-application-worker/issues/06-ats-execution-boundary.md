## Question

哪些 Lever / Greenhouse 页面和动作由首版执行器支持？何时必须停止并交给用户？

限定 URL、嵌入表单、重定向、定制字段和附件动作。决定固定字段映射、已知别名以及新措辞
的等价判断方式与可信判断标准。用户已选择系统判断同义后直接复用，只有不确定时询问。
不得将用户确认的答案来源与系统推导的等价关系混同，也不得只凭相似度扩大 scope。
决定上传前后核验，以及页面变更、登录、CAPTCHA/MFA 和未识别动作的停止条件。
明确执行器如何阻止自动最终提交，并在交接后让用户操作真实页面。

## Answer

### 页面与字段边界

首版沿用现有 Lever / Greenhouse 直接岗位链接规范化规则和岗位身份检查。
用户勾选的原记录限定公司、岗位、国家条件及规范化 URL。
平台内可进入该岗位的申请表；跳转后仍须核对公司、岗位 ID、表单及实际来源。
嵌入第三方公司网站、外部申请系统、搜索页及未验证的页面结构交给用户处理。
资源 CDN 不等于新的申请目标；附件上传服务必须属于已核验的该平台上传路径。

固定字段与控件映射优先复用 label、role、页面必填标记及原生表单能力。
首版支持明确识别的文本、多行文本、单选、多选、选择列表、日期和已选文件控件。
自定义控件须有平台夹具与回读验证；不因名字相似就假定支持。
可选问题缺少答案时留空；必填或含义不明的问题进入补充等待。

### 同义判断与 Codex 调用

先查询明确映射和已知等价关系。新措辞可交给 Codex 等工具作结构化判断。
模型输入为当前题目、候选题目、选项及必要的国家／公司／岗位和时间条件。
不发送答案值、简历、答案库文件、原笔记路径、认证状态或整页截图。
不把 Career Evidence Graph 或简历文字当成申请答案。

输出只含候选问题标识、所问事实、国家／时间／条件、选项对应及不确定原因。
执行器检查候选有效、事实相同、范围兼容、版本有效和选项含义可对应后，才从本地读取答案值。
工作资格与 sponsorship、当前与未来、不同国家及相反选项不能只凭措辞相似合并。
模型给出的置信度不是复用许可；缺失条件、冲突、多候选、无法验证的映射都询问用户。
系统生成的等价关系与用户确认的答案保留不同来源。

可直接复用确定的系统等价判断，不对每个新措辞强制人工首次审查。
缓存绑定题目、选项、范围条件、判断规则及工具／模型版本；答案使用时仍重查原适用范围。
用户纠正关系后旧映射失效。模型超时、限额或无合法输出时，仅该岗位等待；不改用猜测值。

优先复用仓库 codex_cli.py 的无 shell 子进程、JSONL、结构化结果及版本记录模式。
保留现有职业评估适配器语义；仅抽取实际可共用的调用机制，不复用其评估结果契约。
不新增多服务商 SDK、路由框架或自动更换模型。

[官方非交互文档](https://learn.chatgpt.com/docs/non-interactive-mode)支持脚本调用、JSONL、
JSON Schema 输出和保存的 CLI 认证。2026-10-10 本机 CLI 帮助也提供这些参数，
本机版本为 0.162.0-alpha.17.2；这仅证明本地命令存在，不证明本任务模型调用已成功。
实现配置实际客户端路径和模型，记录版本；更新后重新做合成探针，不声称此 alpha 客户端已固定。
已有本机认证由客户端使用，不复制认证文件到仓库、答案库或浏览器目录。

调用工作区只放允许发送的合成或题目元数据；隔离用户配置、MCP、插件和可执行工具权限。
现有 read-only sandbox 不能单独证明限制了文件读取或外部工具访问；JSON Schema 也不能证明语义正确。
实现前须证明受限调用不会读取其他私人文件或调用浏览器／外部应用；未通过时停用该路径。
可按实际客户端支持使用 ignore-user-config 与 ephemeral，但这些参数不是完整数据隔离证明。
记录规则、工具版本、输入摘要、判定来源及失败原因，原始调用记录只留私人运行区域。

### 允许与停止动作

| 动作 | 执行条件或处理 |
| --- | --- |
| 打开岗位及该岗位申请表 | 岗位身份和来源匹配；不扩展到其他岗位 |
| fill、select、check 等字段操作 | 已确认答案在原适用范围有效；字段和控件已识别 |
| 上传简历 | 用户逐岗位选定具体文件与内容版本，批次预览已列明目标和资料；开始操作明确包含填写及上传 |
| 其他附件 | 只有逐项列入本次目标与资料范围才可发送；简历选择不包含其他附件 |
| 网站自动保存与非最终下一步 | 适配器已验证其作用与发送路径，且位于已确认资料范围内；不能只凭按钮文字判断 |
| 模糊按钮、未验证步骤或结构变化 | 停止该岗位并保留页面，不试点未知动作 |
| 登录、CAPTCHA、MFA | 交给用户在专用浏览器处理；同一认证上下文受影响的任务等待 |
| 简历变化、上传错误或身份跳转 | 停止对应岗位，核实新输入及实际页面 |
| 最终 Submit／Send、隐式 Enter、form.submit、申请提交 HTTP 请求 | 执行器没有这些可调用动作；交给用户操作真实页面 |

批次预览与开始操作明确显示哪些资料将发给哪些岗位，不把勾选或选择文件本身当成已发送。
已确定且未变化的范围内不逐文件重复询问。范围扩大、文件变化或未选附件须先由用户补齐选择。

### 最终动作限制与回读

平台适配器只暴露已验证的字段、附件和非最终动作，模型不能输出任意点击或脚本指令。
不向执行器提供 Enter、通用点击、任意 evaluate、form.submit 或申请提交 API。
固定代码可读取页面和回读值；不能把任意页面脚本或模型建议直接作为执行代码。
平台已知最终请求可加辅助拦截；不能封锁所有 POST 来替代动作限制，否则会误阻上传和自动保存。
已有研究指出网络路由有覆盖限制，不能将它描述为覆盖所有脚本／Service Worker 发送路径。

每次动作前复核页面身份与输入版本，动作后回读实际值和错误状态。
姓名、联系方式、地点及选择项必须核对实际选中值；不能只读输入文本或自动完成候选。
附件核对绑定内容摘要、实际控件和上传完成／错误状态。文件名相同不证明内容相同，
控件选择成功也不证明服务器已接收。结果无法确定时进入待核实，不盲目重传。
最后重查全部可见必填提示、未填项和验证错误；新增问题重新进入答案闭环。

回读通过后进入待复核。交接该页面时停止并移除该页自动执行权，保留真实页面由用户操作。
用户人工修改不能被 worker 后续步骤覆盖；需再次自动处理时先显式重新接管并核验。
辅助提交拦截应随交接安全解除，不能阻止用户最终提交，也不能在解除后留下自动提交路径。
暂停批次只停止自动步骤，不阻止用户复核已经交接的页面。
人工提交确认、ATS 接收证据与原记录同步仍按已解决的写回及恢复契约分别处理。

### 验收要求

- 两平台夹具分别验证字段、附件、条件、非最终动作及回读；未知结构停止。
- 同范围的新同义措辞直接复用；不同国家、当前／未来、资格／担保和选项反义不得误复用。
- 模型无合法结果或关系有冲突时询问用户；模型不能读答案库、控制浏览器或增加个人事实。
- 每岗位只上传其明确选定的文件版本；不使用其他岗位附件或未选文件。
- 所有正常、页面变更、超时、错误与恢复路径的自动最终动作次数为零。
- 交接后用户可以在真实页面编辑并提交；worker 不再改写该页。
- 填完、人工已提交和已核验接收分别记录；没有回执不伪报接收。

这些是规划规则，模型推理路径与 ATS 执行器尚未实现或验收。
