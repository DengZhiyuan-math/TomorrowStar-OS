# 内部原 PDF 复用首版：实现与验证

2026-10-19。实现范围：现有准备入口内部尝试已审核原 PDF；不适用、记录不完整或超时即回退现有生成。未增加界面、按钮、确认步骤或局部修改加速。规划票关闭只代表决策完成，本报告单独记录实现验证。

## 已实现

- 按历史 JD 的实际工作内容检索，再检查少量关联 PDF。跨岗位名称和行业；不遍历全部简历正文。历史 JD 摘要按输入、模型配置、结构和代码版本缓存。当前最多处理 24 条合格历史记录、检查 3 个候选；超过历史上限安全回退。
- 只接纳有可验证具体接受记录、完整原 JD 和有效原 PDF 的候选。原 LaTeX 源文件缺失不妨碍验证原 PDF。未审核、已撤销、错误事实、损坏文件、来源关系不完整时不能直接复用。
- 模型适用性检查只消费当前既有已审核内容及纪录事实，不发掘经历、不进行人岗评分。学历等纪录事实保持原有状态，不推断新增事实。新增资料版本导致重评；资料库版本变化保守回退。
- 采用关系绑定新任务、输入版本、分析结果和代码配置；原接受记录仍属于原任务。采用前、持锁落盘前和 PDF 读取时均验证绑定与原字节。手动选择、取消、强制重生、输入变化和未知导出状态沿用原边界。
- 内部记录准备开始到 PDF 就绪的总耗时，以及重复确认请求数。计时包含排队、检索、检查及实际发生的生成/导出；跨进程不可比的时钟记为未知。不要求用户计时或评分。

## 耗时对照

以下基准均为固定合成 JD、资料和合成接受记录，未使用私人材料。历史原 PDF 在计时前创建，两路使用相同当前 JD、资料版本和预存历史。未删除既有缓存，也未人为增加等待。

| 证据 | 正常生成 | 内部复用路径 | 结论 |
| --- | ---: | ---: | --- |
| 离线模型、真实 Chrome/PDF 文本提取，3 对中位数 | 新岗位冷生成 1308.30 ms | 命中 36.50 ms | 该局部基准降低 97.21% |
| 同上，保留同岗位热缓存 | 8.53 ms | 36.50 ms | 热缓存更快，不能声称全部场景提速 |
| 真实配置模型 v3，1 对 | 冷生成 7177.13 ms；热缓存 7.25 ms | 12022.92 ms，未命中后走已热缓存回退 | 未通过真实模型提速验收 |

离线中位数来源：[performance-host-fair.json](performance-host-fair.json)。范围是公开存储生成方法与独立复用方法，包含真实 Chrome PDF 渲染、提取和校验，**不是整个入口的生产总耗时**。确定性模型输出不包含真实模型耗时。

真实模型来源：[performance-live-host-v3.json](performance-live-host-v3.json)。JD 提取 5262.86 ms、候选选择 5776.43 ms，PDF 适用性检查剩余时间不足并失败，触发约 12 秒总预算。返回耗时包含安全回退和运行开销。未命中后使用已保留的热缓存，不能拿它与冷生成比较为提速。v1/v2 失败或未命中结果原样保留。没有以模拟批准替代真实模型决定。

## 验证状态与边界

- **合成软件验证**：已完成命中、回退、读取、接受继承、计时计数、失效和竞争条件检查；离线模型配合真实渲染的局部提速成立。

- **尚未验证**：真实个人材料/人工接受记录的端到端复用、完整正常生成至最终 PDF 的真实模型配对总耗时、真实用户重复确认次数，以及安装版原生应用旅程。未升级安装包、未操作投递。

因此首版代码与软件验证已交付，**“真实模型下确实提速且不增加重复确认”的产品验收尚未通过**。不据此启动局部修改加速。后续应先减少冷检索的模型轮次或提前建立历史 JD 索引，再在相同材料版本上重跑完整入口对照；这些优化本次未实施。
