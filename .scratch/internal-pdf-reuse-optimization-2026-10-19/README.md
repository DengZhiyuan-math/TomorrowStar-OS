# 内部 PDF 复用：真实模型路径优化

2026-10-19。沿用原 12 秒总预算；不增加界面、用户操作或局部修改加速。

## 实现

- 将缺失历史 JD 的工作内容整理与候选选择合成一次结构化模型请求。只保留原文定位正确、核心工作已确认的候选。
- 将最多三份候选 PDF 的适用性检查合成一次模型请求。某一份不适用不再触发下一轮串行请求；模型必须选择已完成原接受记录和字节校验的具体来源。
- 缓存只含 JD 召回结果，绑定目标 JD、历史 JD 集合、模型/规则与代码配置。相同查询再次执行时仍核验原接受、导出清单、实际 PDF、当前资料和新的适用性判断，不继承模型批准。
- 冷查询最多两轮模型调用；同查询已缓存时只剩一轮 PDF 适用性判断。时间预算不变，未知或不完整结果继续安全回退。
- 修复旧来源关联过早去重的问题：先检查来源资格，再对相同 PDF 去重，保留其真实 JD 关联。
- 错误缓存根值安全回退；适用性结论必须绑定实际采用的来源 ID。

## 对照方法

[完整入口基准说明](full-entry-benchmark.md) 定义实际 HTTP 准备开始至普通 PDF 接口可读取并通过哈希验证的总耗时。正常路执行现有完整 LaTeX 生成、既有审核 API、实际本地 Tectonic 编译和 PDF 导出。复用路命中后直接读取原 PDF。

两路固定同一目标 JD、同一资料版本与同一合成已接受历史；不清除已有缓存，交替顺序。模型调用、审核推进、编译和数据读取都计入；人岗匹配已完成且不计入。历史接受与审核推进均为明确合成测试行为，不是实际用户接受。真实模型选项对所有计时内的生成和语义检查调用真实配置模型。

本地 Prism 传输使用测试适配器，调用已安装的 Tectonic，仅用本地缓存；不使用固定 PDF 冒充编译。与真实 Prism、安装版原生应用、真实个人资料和人工审核旅程的差别保留。

这里的计数来自实际入口内部记录，但审核由合成回执自动推进，未测量人工阅读或思考耗时。没有要求用户额外计时或评分。完整端点计时包含 HTTP/排队、模型、检查、真实编译、审核 API 和最终 PDF 读回；内部就绪计时另列在原 JSON，不能与完整端点计时混用。
