# P01–P08 流程职责审查

范围：用户确认的 P01–P08 全流程。比较基准为交付目录中保留的
`installation/source-candidate/payload`，审查对象为本轮源码固定快照。
标准来自 `AGENTS.md`、`CONVENTIONS.md` 和当前开发计划；规格来自
`docs/development-plan.md`、本轮实施地图及各阶段契约。
两个独立审查分别检查代码标准和规格符合性。这里记录源码结论，真实材料与网站接受另记。

## 单一职责

| 步骤 | 只负责的工作 | 交付给下一步 | 下游不应重复的工作 |
| --- | --- | --- | --- |
| P01 | 保存职业正文并派生目录 | 正文、目录、历史与材料关联 | 重新评定自述可信度 |
| P02 | 解读一次 JD | 固定目标、要求、关系和权重 | 重新解释岗位或改权重 |
| P03 | 检索并读完必要材料 | 固定资料包与读取状态 | 重扫已交付正文 |
| P04 | 匹配、推断及计算 | 要求判断、引用、资格和分数 | 再做岗位或可信度审核 |
| P05 | 计划、分经历写作、程序组装、单一终审 | 已审 TeX | 重算匹配；成功作者因无关失败重写 |
| P06 | Prism 编译、接回结果；人工稿仅快速校对 | TeX 对应 PDF 与版本 | 下载或读取时再次编译；人工稿再次内容终审 |
| P07 | 观察解析、保护非空值、集中差异、填写上传 | 最终 Submit 前交接 | 重放未知动作；执行最终 Submit |
| P08 | 连通验证、保全及分层交付 | 可核查证据 | 将合成或源码通过当作真实接受 |

## Standards

### P2：下游失败重做已成功的上游

`career_portal.py:427` 为每次分析分配新随机目录；
`application_matching_pipeline.py:158` 未收到已有说明时重新调用 JD 解读。
因此 P03/P04 失败后重试会重复已完成的 P02/P03，也可能改变已固定的框架。
这与开发计划中固定交付、一步一责和一次岗位解读的要求不符。

最小修正：在任务中保留成功分步交付引用；相同输入时从失败步骤继续。
保留每次尝试和失败记录，不另建通用工作流框架。

### P2：已读完目录仍做必为空的补查

`application_matching_pipeline.py:243` 仅因存在 unknown/partial 再发检索，
未先检查未读候选是否为空。`application_retrieval.py:112` 此时已将选择范围
限制为空；现有单候选 partial 回归也明确期待这次多余调用。
它增加耗时，并让无必要的调用失败阻断已完成判断。

最小修正：没有未读候选时直接交付资料不足结论；有候选时才补查。

## Spec

### P2：只有身份元数据的旧目录项可漏读正文

`application_career_library.py:116` 将非空身份事实当成充分发现信息。
只有机构名、无有效摘要和检索词的旧条目可能得到
`requires_body_discovery=False`，从而跳过
`application_matching_pipeline.py:74` 的正文回退。
这不符合 P03 对不完整目录条目先补索引或读正文的要求，可能漏掉相关技术工作。

最小修正：发现信息须来自有效正文内容；不足时使用既有正文回退，无法读取则报告执行未完成。

### P2：人工校对进入 finishing 后中断无法接续

`application_resume_versions.py:232` 在校对前保存 `finishing`；
但 `finish()` 在 `219` 行会拒绝没有 `draft_id` 的该状态。
即使已有校对结果，原 session 也无法正常继续，与 Flow 允许继续 finishing 的行为不一致。

最小修正：核对已捕获源、已有校对结果和条件写入结果，接续同一 session；
保留原模型尝试，不重复校对或盲目写入。

### P2：跨阶段重试缺少成功交付复用

与 Standards 第一项为同一问题。规格明确要求下游消费固定说明和资料包，
只恢复失败步骤；目前正常路径实现了固定交付，跨阶段失败恢复仍不完整。

## 覆盖与限制

P01 正文、目录和历史已存在；旧条目发现仍有缺口。
P02–P04 正常路径已有固定要求、完整目录读取、独立资格与确定性计分，
缺口集中在目录回退、空补查和失败恢复。
P05 已有分配来源、结构组装、单一终审和局部返工。
P06 已有现存编译结果读取和人工文字校对，仍有中断接续缺口。
P07 已有非空保护、集中差异和未知动作观察；本次不执行真实网站接受。
P08 区分源码、合成、安装和真实接受；需为上述场景补相应回归。

Standards 为两项，Spec 为三项，合并后为四个独立问题；两轴最主要的缺口均是跨阶段失败恢复重复上游工作。
这些是尚未修复的审查发现。此次先修复 JD 引用的空白和大小写对齐；真实材料运行随后暴露小来源串行调用过多，新增有界批量读取修复。两者各自保留回归、安装和真实接受证据，未引入广泛流程重构。

## 本轮真实运行后的后继修正

同一经历的可用正文与补充内容已按原文、归属及边界合并为单一正文，原材料关系及旧版本保留。
资料读取仍只负责交付事实片段：小来源可在同一有界请求中批量读取；每份来源保持独立 ID、原始范围和引用校验。
不能通过批量读取改变匹配结论、缩减完整目录或把执行失败当作申请人缺口。
这项后继修正不消除上方跨阶段重试、空补查、旧条目回退及校对中断的四个问题。

批量读取的真实模型运行另暴露输出契约缺口：单条上下文限制可同时返回空要求关联与否定业务关联，随后被严格校验拒绝。
现将原有相关性约束同步到提供给模型的 JSON Schema，并明确限制说明的要求关联。
原始输出及失败不变，仍拒绝无关联条目，不自动补写关联；此修正不能作为整条真实材料验收已通过的证据。

后续真实读取还返回了内容和偏移完全正确、但跨原字段的引文。现只对新模型输出按既有字段边界作确定性拆分：先核验来源、原文和范围，字段间只允许空白；未覆盖实质正文或字段重叠均拒绝。每片保留原相关性标记并继续严格校验。原模型输出不变，已存回执及复用路径不作修复。独立审查及相关回归通过；完整真实申请接受结果另记于私人验收目录。

最终将读取职责进一步收窄：模型只选择来源、逐字引文及相关要求；程序在当前提供范围中定位唯一原文并计算位置，然后执行字段拆分和严格校验。不存在、重复或范围外的引文失败，新模型输出不得自行计算偏移。历史回执不经过新定位路径。私人失败记录现保留具体异常原因。这直接消除了模型重复做位置算术的职责混淆；上方四个独立审查发现仍未修复。
