对应[重开App后明确恢复准备进度](../gmail-resume-preparation-2026-10-17/issues/11-preparation-lifecycle-recovery.md)，沿用 `preparation-policy/v1.0`。最终通过数、选择范围与命令见 [verification.json](verification.json)。

## 恢复契约

中断的排队／执行阶段追加恢复记录，保留原阶段、尝试、输入代次、输入摘要、JD 绑定和原因。重复读取或重开已恢复／已完成任务不新增中断，也不排入模型或导出。已完成分析、草稿、草稿审阅、PDF、材料确认和历史快照保留。

分析／草稿中断需要明确重试；排队但未开始的 PDF 标为已知未开始；运行中的 PDF 标为待核验，先读取原保存回执。已知 PDF 失败保留有效草稿与审阅，只显式重试导出。批次保持暂停，待处理岗位仍遵循手动重试；材料确认仍停在等待申请结果记录。

关闭和结果采用共用原应用锁。若结果先完成检查点，则保留该完整结果；若关闭先取得边界，则晚返回不能成为当前结果。原执行器仍活跃时保留 owner 锁，新实例只能查看，不能重试接管。没有新增 worker、存储或自动恢复调用。

准备页面显示运行会话、实际已加载的准备引擎代码及稳定常量摘要、Python／包版本和实际返回的 UI 字节摘要；另展示任务身份、输入代次与 JD／来源／配置绑定。运行身份在启动时冻结，不能用后来磁盘上的源码假称已加载。该摘要是准备引擎的诊断身份，不是整包签名、依赖完整性证明或安装版验收。

## 当前退出故障

本轮真实后端 SIGTERM 测试两次得到 Python `_enter_buffered_busy` / stdin `BufferedReader` 关闭锁错误。最小差分去掉 HTTP、任务与关闭线程后仍可复现；改为原始读取后正常退出。最终在原后端使用原始输入流，保留内存流兼容性。

[诊断记录](shutdown-diagnosis.json)和[最小差分](stdin-shutdown-differential.json)保留原始失败。首次修复的原生检查通过，但旧内存输入夹具有3条线程警告；改正后的相关检查将线程警告视为错误仍通过。所有 RED、失败、警告及修正后的日志均保留原貌。运行指纹测试中的首次模块名拼写错误也保留，没有记为行为 RED。

此处只修复新复现的准备后端退出路径，不据此关闭此前 App、Chrome、Cua 或原页恢复调查。

## 验收边界

源码和隔离合成恢复验证。未读取私人资料或真实邮箱、调用真实模型／岗位／ATS、上传、Submit、恢复旧申请／填写器、启动或替换安装版 App、提交 Git 或写远端。PDF 模板与 renderer 未修改，本票的复制 PDF 夹具不增加实际 renderer 质量声明。安装、整包候选冻结、真实试用和真实人审继续由后继票验收。真实申请继续暂停。
