## Question

如何在现有材料路径中接通用户确认的分经历生成，让真实Codex subagents分别读取来源、交付片段，再由程序组装完整main.tex，单一终审后沿用编译与采用路径？

## 实施前事实（保留）

仅有[设计文档](../../../docs/resume-agent-generation.md)，尚无新运行接口或生成实现。当前完整生成仍为application_full_latex.generate_full_latex及_model的单请求路径。来源选择是selected_source_ids，不能直接当经历ID；需从现有职业记录建立经历及所属来源对应，无法归属时不凭标题猜测。

现有application_prism.source_snapshot只接受独立TeX，拒绝input/include。因此首版将候选片段由程序拼入单文件main.tex，复用当前编译，不扩展多文件协议。写作者仍分别交付片段，不共写main.tex。

## Acceptance criteria

- [x] 沿用设计的五项接受条件，明确已有来源如何对应选中经历；一经历一写作者，实际Codex分派，非选中来源不进入写作请求。
- [x] 提供主agent可调用的准备/读取与片段交回、程序组装及终审交回入口；不要求App内置多agent平台，失败结果不静默省略。
- [x] 正文片段及来源说明持久保留，程序唯一写入main.tex；当前学历、联系方式及人工稿/省略规则保持。
- [x] 终审针对实际组装稿、JD和来源说明，记录具体问题与修订；通过后编译，编译成功直接消费PDF，不增加用户审批。
- [x] 超过旧整库请求限制的合成资料可通过分经历读取完成；部分失败可保留已完成片段，仅恢复对应经历。
- [x] 受影响行为回归及共享合同所需完整离线验证通过；明确区分假agent测试、真实Codex编排和实际简历质量。无实际subagent执行证据不能声称整链已验。

## Ownership and boundary

领取后再修改共享材料、来源读取与测试；协调现有Flow/Resume/Prism文件负责人，不回退现有修改。不在本票更新App或重放旧申请任务。

## 实施顺序与待核对点

以下是本票内部顺序，不拆成新的长期票队列。领取者负责来源到片段、组装、终审交回和材料采用的完整源码路径；验证可由独立agent协助。现有共享文件有其他负责人时先协调，仅在确认互不修改同段代码时并行。

### 先准备按经历分派的任务

复用application_resume.career_source_snapshot、ApplicationResumeStore._task_current及analysis.selected_source_ids。当前选择的是来源，先从既有经历记录和Contribution关联建立本次经历清单；优先使用已有ID和来源定位，不以同名标题推断归属，也不新建职业事实库。资料型职业经历不因缺研究inventory接受或Skill评分而被禁止使用。

一经历可含多个来源或Contribution，不能直接一source一agent。已有底稿优先使用已保留的review_groups及来源关联定位正文；缺失关联时由主Codex读取实际底稿给出明确对应，再交程序核验，不用静默按行号或标题猜测。来源跨经历时保留实际归属和局部引用；重要歧义才向用户询问。

准备结果只给写作者本经历的来源入口、相关JD、实际已有文字、人工编辑/省略记录和篇幅目标。来源内容按需读取；整库出处可由程序本地留档，但不整体加入任一模型请求。不得仅把128000字节保护调大或静默截断输入。

### 接通Codex工件交接

主Codex读取经历清单并用实际subagent工具分派，复用会话现有并发容量分批运行，不在Python后台建立第二套agent平台。每位写作者独占自己的候选片段和来源说明；程序是main.tex唯一写入者。

提供主Codex可调用的薄入口：准备任务与读取来源定位、接收片段并组装、记录终审结果并采用。入口形式沿用当前CLI/Store边界，不要求用户手工搬运文件或逐段批准，不创建新服务或另一套状态机。具体函数/命令名由实现选取最小一致方案。

只使用现有任务、输入版本、底稿和来源绑定校验结果是否仍适用。已完成片段保存到现有材料版本目录；某写作者失败只处理该经历，输入改变只影响相应片段。程序核对本次选中集合、重复/缺失和来源身份，不把未选经历静默加入。

### 程序组装，单一agent终审

复用application_full_latex现有分组核验、学历/联系方式保护及人工稿更新行为，将片段拼入独立main.tex候选；不使用input/include，不另写完整生成器。未知模板位置由主Codex核对，实际稿未被核验前保持原字节。

终审agent读取组装稿、JD、片段来源说明并按需查原始证据。记录通过或具体修订项；结果对应实际候选内容和当前输入。修订后重组并复核，不能把对旧稿的通过用于新稿。终审只给意见，修改由对应写作者/主Codex发起后经程序组装，不直接与写作者共写主文件。

采用与导出复用ApplicationResumeStore.save_automatic_source及export_for_draft、PrismClient.compile等现有能力；若具体采用入口不兼容新片段，扩展现有边界而非建立新材料库。候选成功采用后，当前任务仍沿原PDF消费方式继续。

现有App自动生成按钮不能自行调用当前聊天的subagents。实现应让该入口显示当前生成进度和需要Codex完成的步骤，主Codex通过上述工件入口接续，不能回退为整库一次模型调用后宣称多agent完成，也不要求App独立运行。

### 验证后交付安装候选

先做合成行为回归：多经历分派与稳定顺序、一经历多来源、超旧总输入限制的按需读取、来源/片段错配和缺失、人工编辑与省略保留、仅受影响更新、部分失败恢复、终审后内容变化使旧结果不适用，以及固定学历保持。复用已有测试辅助，不测试与实现逐行相同的内部细节。

共享材料/存储合同变化后跑完整默认离线及静态检查。随后由主Codex在明确标为合成的资料上实际分派多个写作者和一个终审agent，经程序完成main.tex与编译，保留结果；假模型回归不能替代这项真实编排证据。真实个人简历质量留到使用中观察，不以真实投递作为本票验收条件。

交付内容为可调用入口及用法、生成材料/片段/终审记录、源码与验证范围、未支持的准确边界和安装候选所需变更清单。未完成这些内容时不声称已实现或已安装。

## 2026-10-22 实施结果

已交付薄 CLI/Store 工件入口、按经历来源映射、片段与读取说明、程序组装、独立终审和现有材料采用/导出。最终完整默认离线：4819 passed、2 skipped、572 deselected；静态检查通过。真实两个写作者和一个终审 agent 在 164461 字节合成资料上完成编排，精确候选真实本地编译为一页 PDF，并由现有材料存储保存。实际 Prism HTTP、安装版和个人简历质量不冒称已验收。
