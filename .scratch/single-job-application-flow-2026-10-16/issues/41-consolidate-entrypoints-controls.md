## Acceptance criteria

- [x] 默认入口统一使用现有主编排；handoff/lab/preview中仍有用途的功能调用共享模块。旧外部handoff的claim/人工提交声明/回执链不再作为默认人工页面操作步骤。
- [x] 常用控制为开启、暂停、继续和跳过；人工修改后一次继续，移除重复接管、来源表单、批准和“我已提交”例行按钮。未知结果仍可要求必要答复，不能隐藏真实问题。
- [x] 周期更新保留稳定控件与编辑焦点；fetch有具体操作超时，局部错误只限制依赖该动作的工作。暂停和查看始终可用；查看历史与跟随当前岗有明确行为，不永久丢失新岗跟随。
- [x] 持续收录不禁用查看既有任务；界面分别显示本地收录、标签/归档和后续JD状态，提供skip与返回原岗入口，不把取消当跳过。
- [x] 旧活动任务/claim保留明确兼容入口、原owner/page/附件/人工编辑及未决结果；不能为更新抢占或重启。只删除确认无调用、无活动依赖的代码，不要求所有历史活动归零才能交付本票。
- [x] 无效模型路径和无关备用目录的能力降级由运行检查票提供，本票显示其准确错误和修正入口，不再误报为所有资料目录故障或另建一套就绪审批。
- [x] 更新当前导航和相应用户操作说明；历史收据可读，旧教程不再支配当前流程。回归主要控制、键盘焦点、编辑保留、局部故障、当前岗跟随和旧任务兼容。
- [x] 提供实际删除/共享的入口、按钮和控制分支清单，不以代码行数或“所有旧模块都删除”作为唯一验收。完整主App组合由下游现有组合票负责。
