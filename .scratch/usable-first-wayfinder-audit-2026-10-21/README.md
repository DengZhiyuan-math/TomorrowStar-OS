# 当前工作审计与可用优先重排

2026-10-21；使用 wayfinder 重新整理现有地图。本轮交付是已落盘的票据、优先级、依赖和导航，不是又一轮源码实现，也没有关闭、领取或替用户接受任何票。唯一当前顺序在[开发计划](../../docs/development-plan.md)，本文件是审计快照。

## 审计结论

主流程并非还要从头建设。持续收录/顺序队列、匹配分流、完整材料和必要附稿、原页材料换版、一次继续、skip/return、人工 Submit 结果消费及默认统一入队已形成源码证据。长期未勾选的旧框、原 owner 和粗粒度整票依赖把“源码未写”“已写待安装”“真实/用户接受”混成一条长等待链，导致下一项功能难以领取。

确证的小缺口是：生产启动没有向 Intake 注入用户的 processed_label；默认界面没有消费已具备的独立邮件处理进度。Ashby 岗位读取已有，组织初始化在当前操作支持表/回归中仍缺，下一步须从真实 Runner 公开入口补失败用例确认并修复。Workable 普通 resume 有合成证据；autofill 与必要附稿仍应按具体目标补。不能以这些有限缺口为由重写控件、材料引擎或持续队列。

当前 Flow 执行状态副本仍写入并参与重开，是真实的稳定性源码收尾，但不应要求全仓状态重构先结束才允许验证已支持功能。任意 SSO/跨路径导航缺一个明确实例时，先保留准确限制，不预建平台大全。

## 现在先做什么

1. **首先领取 [接通邮件处理设置与独立进度展示](../single-job-application-flow-2026-10-16/issues/42-mail-processing-settings-status.md)**：一张 P0、open/none、仅源码与合成的有限交接，复用后端接口，设置及状态实现细节唯一存该票。原邮件/默认入口票继续持有整体验收并等待这份产物。
2. **[核验 Ashby 公开初始化读取的精确请求边界](../single-job-application-flow-2026-10-16/issues/33-ashby-public-bootstrap-review.md)**：可与邮件设置并行：先补岗位/组织公开初始化，不重造 Query 审批，不重试历史未知 open。
3. **[支持 Workable 普通简历字段的受控上传与回读](../single-job-application-flow-2026-10-16/issues/20-workable-resume-upload.md)**：由原负责人继续：仅补目标需要的 autofill/附稿；保留已通过普通 resume 路径，不等待整个通用控件票结案。
4. **随后集中一个主 App 候选的最小安装旅程**：消费已有实现和新配置，只对明确支持路线作结论，提供未支持项/恢复/回滚记录。完整 APP 验收和用户真实体验仍在各原票；有限候选不代表整票可关闭。

App 更新与真实申请继续暂停，源码建设不能替代这项发布边界。本轮没有更新/启动 App、模型调用、邮箱修改、真实表单动作或 private workspace 写入。最终 Submit 继续人工。最早用到新能力仍需要后续一次集中主 App 更新与安装验收，不把这些审批复制到每次业务动作。
