状态：J04 已重构现有读取、匹配与阶段恢复入口，源码验收状态见[JSON 实施地图](../.scratch/json-resume-delivery-2026-10-24/map.md)。P01 已增加[经历正文及派生目录源码入口](career-experiences.md)，P02 已交付[固定岗位框架](job-brief.md)，P03 已接[完整目录与固定资料包](material-packet.md)。P04 已接[受控推断、区间和独立覆盖展示](match-inference.md)。真实私库及模型语义接受与 P05–P08 保持各自待验范围。唯一实施顺序和验收状态见[开发计划](development-plan.md)及[实施地图](../.scratch/resume-agent-delivery-2026-10-22/map.md)。旧实现的目录、来源快照和历史 receipt 不代表本文完整新协议已完成。

## 库职责与默认检索单位

| 位置 | 唯一职责 |
|---|---|
| 基础信息库 | 保存个人事实、申请答案、偏好和适用范围，提供完整经历目录统一入口 |
| 职业经历库 | 以经历条目保存完整事实正文，关联补充资料与查看产物 |
| 经历目录 | 从职业经历内容自动生成和同步，不独立手工维护第二份经历 |

所有经历都保留可发现入口，不按当前 JD 提前删除背景。新经历以 `experience-facts/v1` JSON 保存逐条事实、来源引用、责任、状态和范围。已有旧正文保留兼容读取，显式导入后才发布为结构化事实。内容包含身份、机构、角色、时间与状态、背景目标、实际工作、方法技术及用途、合作交流、结果产物及关联入口。没有记录的字段可为空；不要求补足成果数字或审核评分才能入库。

摘要不能代替完整正文。目录包含固定经历 ID、名称/类型、机构和已有别名、时间/状态、内容摘要、检索词、关联经历/仓库/论文、详情入口。摘要与检索词分别从正文及相关细节提取，不仅从短摘要生成关键词。内部内容版本及索引状态用于同步，不展示为资格，也不参与评分。

仓库、论文和子项目可有独立资料入口并与经历关联，不强迫每个仓库成为独立职业经历。目录列经历与有独立信息价值的资料，不把项目每个文件变成同等候选。

## 整理、去重与增量同步

资料按用途分为主要正文、按需补充资料、查看产物/历史。同内容 TeX 与导出 PDF 只索引一次，保留源与产物关系；有独有批注或内容的资料保留新增信息，不能按扩展名直接排除。生成的定制简历/PDF 不反向成为新经历事实。人工明确补充事实写入对应经历；纯简历措辞修改不自动入库。

首次完整整理归并已有资料，提取独特事实，合并重复表达，检查“有正文无目录”“详情失效”及独特事实遗漏。不同任务、时间、技术用途、个人与团队角色及结果版本不能被误合并或累计。检查对象是整理是否忠实、是否遗漏，不是自述可信度，不重复要求用户证明。

新增/修改经历时保存正文并仅更新受影响目录及关联条目。仓库或论文变化按已有关系更新受影响内容，不每次扫描整个库。摘要生成失败也保留基本目录与详情入口，标明索引未完成；不能让该经历消失。保留人工正文修改和旧历史，不每次重写全篇。明确更正替换当前事实并留历史；只有已有记录无法解决的实际冲突才提出针对性问题。

## 一次岗位解读与按需读取

岗位解读在检索前一次完成，交付业务目标、工作产出、固定要求及业务分组权重。所有后续步骤复用，不各自重解 JD。复合条件拆开检索、分别判断，展示汇总；子项共享原要求权重，不因拆分增加总权重。P02 已交付[固定框架与样例规则](job-brief.md#计分规则)，不固定 required/preferred 比例；P03 已接完整目录及分段读取；P04 已接固定推断结果，下游写作仍按 P05 实施。

每个岗位读取全部当前轻量目录，再按岗位说明选择候选并读取必要正文及关联资料。关键词、别名和模型语义理解结合，不只查标题，不以固定 top-K 或词频作为唯一候选范围。结构化事实作为完整单元读取，模型只选择程序提供的来源 ID 及适用要求；程序取得该事实全文和来源引用。旧长原文仍通过详情 Adapter 分段，模型选择程序提供的段落 ID，程序还原原文与范围。已选候选超单次上下文则分批，不静默截断，也不让模型复制全文或计算字符偏移。每次投递不重建目录，也不读取全库原文。索引待补、只有标题或摘要/检索词不完整的条目，不能凭标题直接排除：先补该条目录或回退读取正文，无法完成则标记 `execution_incomplete`，不静默宣告检索完整。

检索只找资料，不决定匹配分或最终简历选材。输出固定的 `material_packet`：经历事实、必要原文细节、适用信息及内部定位。重复命中合并读取。匹配出现 `unknown` 或 `partial` 时，先比较完整目录与实际已读候选集合，包含自动展开的关联候选。集合已耗尽时直接交付实际资料状态，不发起空补查。只有仍有未读候选时才请求定向补查；补查没有新增选择则结束，不自行重扫并审核全部库。

检索完成需同时满足：目录入口完整、查找方向覆盖岗位要求、相关候选必要内容已读、读取状态明确。三种结果严格分开：

| 状态 | 含义 |
|---|---|
| `retrieved` | 已取得资料，交给匹配判断 |
| `information_insufficient` | 完成查找后没有形成判断所需的记录 |
| `execution_incomplete` | 已知资料尚未读到、读取失败或被截断；不是能力不足 |

路径、引用及内容绑定用于正确读取和归属，不是再次可信度审核。未知操作结果先核对，不更换请求 ID 盲目重放。一次交付后下游消费固定结果，不在展示、写作或导出时重扫实时库。显式刷新才采用新输入；旧分析、TeX、PDF、附件及历史不因此全局失效。

## 阶段恢复与已完成分析复用

现有 `analyze_job(..., resume_from=...)` 接收原分析目录；Flow 的显式失败重试
通过尝试 lineage 传递该目录，不要求用户手工拼接工作流。每次恢复创建新分析目录，
保留原失败目录、阶段结果和尝试记录。岗位、资料、配置及固定要求的绑定不符时，
拒绝接续旧尝试。

| 原阶段状态 | 接续行为 |
| --- | --- |
| P02 已保存有效 `job_brief` | 校验岗位绑定并复用，不重新解读 JD |
| P03 已保存目录计划、读取回执和资料包 | 校验输入与读取作用域，复用成功结果 |
| P04 已失败，上游成功 | 保留原固定岗位说明和资料包，只接续评估 |
| 响应已保存，但最终结果未发布 | 核验原输入、提示词和 Schema，能采用时在本地完成发布 |
| 当前阶段已有明确失败结果 | 由显式重试创建新尝试，只重试失败阶段 |
| 调用已发出，但结果未知 | 返回 `match_result_needs_recheck`，先核对原调用，不盲目请求模型 |

恢复中的读取失败仍是执行问题，不能转为能力不足或资料不存在。部分成功读取
只在相同来源及作用域下复用；成功阶段不因下游失败而重新调用模型。

已完成分析另走语义复用校验。程序核验原分析、固定资料包和评估绑定，再比较本次
已消费资料。未选来源变化或纯诊断元数据变化，不自动废弃已完成分析。实际事实文本、
来源引用、责任、状态、适用范围、教育或适用基础信息、JD，以及影响推断的配置变化，
不能借此误用旧判断。复用保留原事实 ID、原资料包及推断引用，另存当前输入绑定，
不重写旧报告或人工修改。此规则不等于失败尝试可忽略输入变化继续执行。

## 匹配与受约束推断

匹配评价完整背景与岗位的适配，不受简历篇幅和选材限制；匹配资料覆盖与最终简历覆盖分别展示。明确资格门槛单列，不能由其他优势抵消。满足、不满足、资料不足分开；不满足需实际事实不符，不能以缺字段、自述、无考试或未做能力审核作依据。整体分数未确定时显示匹配区间，按固定组关系结论确定后显示单分；执行未完成不伪装为低分。

应用流程接受两库内容，不审核可信度。自述语言等级直接使用；明确考试要求另判断考试事实，不降低语言水平。大型项目未完成研究审核或 Skill 评分暂不参与应用流程，不补造结果。保留实际角色、日期、计划/完成状态和答案适用范围。

匹配模型可以依据实际内容推断语义，不要求同名字段：例如已有数学/计算工作应用于连接组学可支持跨学科经历，具体 Python 工作可支持编程要求。金融研究先理解业务目的，区分直接业务经验与可迁移方法，不能靠 Quant/数学/Python 词频替代业务关联，也不能补造 JD 未要求的门槛。

推断接口接收固定岗位说明、要求与权重、事实包和 `inference_policy`，输出要求 ID、`direct`/`deterministic`/`semantic` 类型、事实引用、判断、简短依据与可用表达范围。程序计算日期等确定性结果，约束要求/事实 ID 与权重，执行算分；不能声称 JSON Schema 或引用存在证明了语义正确。语义推断不自动降权，不生成新的精确等级、数字成果或职责身份。

推断只作为本次匹配及写作依据，不自动回写永久信息库。下游复用推断，不增加第二审核 agent。引用错误是本次输出错误，属于执行问题，不能转换成申请人资料未知或能力缺失。

## 实施与行为验收

按主计划实施，不能以手工候选名单、单个岗位逐条特判或临时改分代替正常链路。至少覆盖：

- 目录完整、别名与关联有效，正文/目录增量一致，整理失败条目仍可发现。
- Crossfield Lab（合成名，真实项目留私库）从跨学科工作语义召回；Python 标题缺词仍可由正文/关联仓库召回；不是固定名称白名单。
- 已保存的英语及其他语言自述等级正常复用，无考试或未审核不降级。
- 删除能力标签但保留具体工作、改项目名但保留技术内容，判断保持语义一致；重复 PDF/TeX 不增加匹配分。
- 读取失败、上下文截断及错误引用不进入能力扣分；实际缺记录与执行错误有不同状态。
- 业务分组和复合拆分权重守恒，资料不足区间、完整单分与简历覆盖分离。
- 目录已读耗尽时不空补查；仍有未读候选时保留定向补查。
- P04 失败后保留固定 JD 解读和读取产物；未知调用结果阻止盲重放，原失败记录不覆盖。
- 已完成分析按已消费事实复用；未选来源或纯诊断变化不使旧结果全局失效，实际语义变化不能误复用。

测试采用离线正例、反例和变形样例控制推断行为，区分模型质量与程序可验证边界；不为每次推断叠加实时复审。未来向量可辅助召回和成本控制，不是匹配分、能力评分或当前必需依赖。当前先完成完整轻量目录与按需原文链路；向量不作为唯一候选范围。
